# Hysteria2、Vless、AnyTLS：代理协议到底该选哪个

一句话结论：**网络质量差、丢包多的时候 Hysteria2 通常更稳；网络本身正常、但怀疑被 QoS 限速或用不了 UDP 时，Vless 这类基于 TCP 的协议更可靠；AnyTLS 则适合在协议特征容易被识别时当备用。** 最实际的做法是几种都留着，按当下的网络环境切换。

## 一、根本差异：走 UDP 还是走 TCP

| 协议 | 传输层 | 常见封装方式 |
| --- | --- | --- |
| Hysteria2 | UDP | 基于 QUIC，自带拥塞控制 |
| Vless | TCP | 基于 TLS，常见搭配 Reality 或 XTLS |

这个差异决定了两者在不同网络环境下的表现完全不同：**UDP 被限制的地方，Hysteria2 直接不可用；TCP 拥塞严重的地方，Vless 会更难受。**

## 二、四个维度的对比

| 维度 | Hysteria2 | Vless（TCP + TLS） |
| --- | --- | --- |
| 弱网与丢包环境 | 表现更好，丢包严重时仍能维持可用带宽 | 丢包时速度下降明显 |
| 运营商 UDP 限制 | 容易被限速甚至直接阻断 | 不受影响 |
| 延迟表现 | 打游戏时通常更跟手 | 稳定性好，但拥塞时延迟波动更大 |
| 资源开销 | 相对更吃 CPU 与电量 | 更省电，适合长时间待机 |
| 特征对抗 | 依赖协议自身的混淆能力 | 配合 Reality 时 SNI 层面的对抗更成熟 |

补充一句：Hysteria2 的拥塞控制比较激进，在带宽紧张的网络里可能挤占同线路其它应用的速度，这也是部分场景下它"很快但别人卡"的原因。

## 三、AnyTLS 又是怎么回事

近两年出现的 **AnyTLS** 走的是另一条思路：仍然基于 TLS/TCP，但通过填充策略降低流量特征的可识别度。它在客户端支持上依赖版本——Shadowrocket 与 Mihomo 内核较新的版本已支持，但老版本客户端可能识别不了订阅里的这类节点。如果你的客户端版本较旧，遇到"某些节点不显示"时不妨先升级客户端。

## 四、按场景选

* **手机移动网络、信号时好时坏**：优先试 Hysteria2，它对丢包的容忍度更高。
* **有线宽带、家用路由器**：Vless 更省资源，长时间挂着也更省电。
* **校园网、公司网络、部分公共 WiFi**：先用 Vless，这类网络经常限制 UDP。
* **晚高峰视频卡顿**：先测两者在同一时段的实际速度，不要只看延迟数字。
* **打游戏**：以延迟抖动为准，通常 Hysteria2 更稳，但要在实际游戏里验证。

## 五、实践中的用法

不需要纠结"哪个更好"，正确做法是：

1. **两种协议的节点都留在订阅里**，用延迟测试筛出各自最快的两三个；
2. 日常用一个，遇到异常时切到另一种协议对比——这一步能立刻区分"是节点问题"还是"是协议被针对了"；
3. 客户端里把常用节点固定成策略组，切换时少点几下。

需要提醒的是，协议只是影响体验的因素之一。**同一协议下，线路质量（中转还是专线）对你的实际体验影响往往更大。** 判断线路差异的方法见[机场套餐怎么选](plan-choosing-guide.html)。

## 六、出现这些症状时，先换协议再排查

| 症状 | 优先怀疑 |
| --- | --- |
| 只有 UDP 类节点全部超时，TCP 类正常 | 当前网络限制 UDP |
| 视频能播但游戏频繁掉线 | 当前节点的延迟抖动过大 |
| 刚开始很快，几分钟后掉速 | 拥塞控制被运营商干预，换 TCP 类协议试试 |
| 所有协议都慢、但只在国内网站慢 | 与协议无关，是本地网络本身的问题 |
