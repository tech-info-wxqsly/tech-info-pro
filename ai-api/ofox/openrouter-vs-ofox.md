# OpenRouter 和 Ofox 怎么选：国内场景该看哪几点

两家都是「一个 API Key、调多家厂商模型」的聚合服务，放在一起比很自然。但它们其实是给两种人准备的：OpenRouter 面向全球开发者，模型目录最全；Ofox 面向国内网络环境，先解决「进得去、付得掉」，再谈模型多不多。

这篇不评谁更强，只把几个维度的差别摆出来，最后说清楚在国内写代码的场景里，我为什么更推荐 Ofox。

## 一张表先看差别

| 维度 | OpenRouter | Ofox |
| --- | --- | --- |
| 模型覆盖 | 官方文档口径 400+ 个模型、80+ 家提供商 | 100+ 个模型、十余家厂商 |
| 接口协议 | 以 OpenAI 兼容为主 | OpenAI / Anthropic / Gemini 三种都提供 |
| 国内直连 | 官网和 API 端点都需要能访问境外 | 只有注册/充值需要；接口走 `api.ofox.io`，国内直连 |
| 付款方式 | 国际信用卡、支付宝（覆盖有限）、USDC | 支付宝、微信 |
| 控制台语言 | 英文 | 中文 |
| 充值时的手续费 | 收平台手续费（Standard 档约 5.5%） | 以官方价目页为准 |

> 表里 OpenRouter 的信息取自它的官方文档与定价页，2026-10 核对；手续费分档与支付方式调整得比较勤，下单前请以官方页面为准。

## 一、模型覆盖：OpenRouter 更全，这一点不用争

如果你要的是「什么模型都能找到」，OpenRouter 更合适。它的官方口径是 400+ 个模型、80+ 家提供商，热门开源模型、刚发布的新版本，往往第一时间就上架。

Ofox 的目录小一些，但覆盖的是国内开发者真正在用的那一批：Claude、GPT、Gemini、DeepSeek、通义千问、豆包、智谱 GLM、Kimi、MiniMax、Grok 等十余家厂商，另外还有万相、Seedance、Nano Banana 这类图像与视频生成模型。具体清单见 [Ofox 实测](index.html) 里的那张表，或者直接请求 `https://api.ofox.io/v1/models`。

**取舍很清楚**：要「全集」选 OpenRouter，要「常用的都在、而且拿得到」两边都能满足。

## 二、接口协议：Ofox 多给两套原生协议

OpenRouter 的接口以 **OpenAI 兼容**为主，这也是它被大量工具内置支持的原因——任何认 OpenAI 格式的客户端都能直接接。

Ofox 在 OpenAI 之外，还提供 **Anthropic 与 Gemini 的原生协议**。这个差别在具体工具上会体现出来：Claude Code 用的是 Anthropic 协议，接 Ofox 时直接把 `ANTHROPIC_BASE_URL` 指过去即可，不用在中间再加一层转换。配置步骤见 [Claude Code 接入配置指南](claude-code-setup.html)。

如果你手上工具杂、协议各不相同，多两套原生协议能省掉一些折腾。

## 三、网络可达性：国内用户最容易卡住的一步

这是两家差别最大、也最容易被忽略的地方。

**OpenRouter**：官网和 API 端点都需要能访问境外网络。也就是说，你本地跑 Claude Code、Cursor 这类工具时，得**一直挂着代理**，否则请求根本发不出去。

**Ofox**：只有**注册和充值**这一步要能打开官网（`ofox.ai` 在大陆打不开，需要先解决网络）；真正调用模型时走的是 `api.ofox.io`，**国内网络可以直连**，日常使用不需要挂代理。

换句话说：OpenRouter 的网络要求是「全程」，Ofox 是「只在开号那一次」。对每天要写代码的人来说，这个差别很实际——代理断一次，工具就停一次。

> 还没解决网络问题的话，先看[机场实测与线路选择](../../airport/index.html)。

## 四、付款：都能用支付宝，但 Ofox 多一个微信

OpenRouter 支持国际信用卡、支付宝（覆盖范围有限）和 USDC 加密货币充值。

Ofox 支持**支付宝和微信**，扫码即充，不用为它单独办一张境外卡。

两边都能支付宝这一点值得说清楚——不要把「支持支付宝」当成 Ofox 独有的优势；它真正多出来的是**微信**，以及不必为充值去处理境外支付流程。

## 五、计费与手续费

两家都是按量计费、没有订阅，费用随用量走。差别在充值环节：

OpenRouter 在充值时收一笔平台手续费（Standard 档约 5.5%，Business 档 8%，具体以定价页为准），模型本身按官方价计费。

Ofox 的计费方式是按量扣费，单价以官方价目页为准。想估算自己的月成本，可以看 [聚合 API 的成本怎么算](pricing-guide.html)——Token 计费和流量计费是两笔完全不同的账。

## 什么情况选 OpenRouter

* 需要**最全的模型目录**，尤其要用冷门开源模型或刚发布的新版本；
* 手上有**国际信用卡**，且能接受**常驻代理**；
* 主要工作环境在国外网络下，或者你已经有一套稳定的代理方案。

这些场景 OpenRouter 做得很好，不用勉强自己换成别的。

## 为什么在国内场景我更推荐 Ofox

如果你的情况是「在国内、用 Claude Code / Cursor 这类工具写代码」，那大概率是 Ofox 更省事：

1. **日常调用不用挂代理。** 接口走 `api.ofox.io` 国内直连，只有注册和充值那一次需要网络条件。这是最直接的省心点。
2. **付款方式对国内用户友好。** 支付宝、微信都能充，不用为它办境外信用卡，也不用碰加密货币。
3. **三种协议原生支持。** Claude Code、Gemini SDK 这类工具可以直接指过来，中间不用加转换层。
4. **中文控制台。** 看用量、查模型、对账都在中文界面里，出问题少一层翻译成本。
5. **常用模型齐全。** Claude、GPT、Gemini、DeepSeek、Qwen、豆包、GLM、Kimi、MiniMax 这些主力都在目录里，还带图像、视频生成模型。

代价也要说清楚：**模型目录没有 OpenRouter 那么全**，如果要找非常冷门的模型，Ofox 不一定有；另外它对延迟敏感的关键业务同样多一跳中转，建议先小额实测再放量。这两点在 [Ofox 实测](index.html) 的「适合谁，不适合谁」里有更细的说明。
